### 总览
```
// Nginx 高性能的 6 大支柱：
// ① IO 多路复用（epoll）—— 一个线程管海量连接
// ② 异步非阻塞 —— 不等待，事件驱动
// ③ 多进程 + CPU 亲和 —— 充分利用多核、无锁
```

### IO多路复用 epoll
先理解阻塞的代价
```
// 传统的 BIO（阻塞 IO）：
// 一个连接一个线程，read() 时线程阻塞等待
// 1 万连接 → 1 万线程 → 内存爆炸 + 上下文切换爆炸

// 多路复用：一个线程监听多个 fd
// 哪个 fd 就绪就读哪个 → 无需为每个连接开线程
```
select/poll/epoll对比

|维度|select|poll|epoll|
|---|---|---|---|
|**fd 数量限制**|1024（FD_SETSIZE）|无上限|无上限|
|**时间复杂度**|O(n) 遍历|O(n) 遍历|O(1) 事件驱动|
|**数据拷贝**|每次全量拷贝 fd 集合|每次全量拷贝|内核维护，无需重复拷贝|
|**触发方式**|水平触发|水平触发|水平/边缘触发|
|**适用**|少量连接|少量连接|海量连接|
```
// select 的问题：
// ① 每次调用都要把 fd 集合从用户态拷到内核态（O(n)）
// ② 内核要遍历所有 fd 检查是否就绪（O(n)）
// ③ fd 数量限制 1024

// epoll 的优势：
// ① 用红黑树维护 fd，增删查 O(log n)
// ② 用就绪链表，只返回就绪的 fd（O(1)）
// ③ epoll_wait 直接拿到就绪 fd，不用遍历
```
epoll的三个核心操作
```
epoll_create();   // 创建 epoll 实例（红黑树 + 就绪链表）
epoll_ctl();      // 增删改要监听的 fd
epoll_wait();     // 等待就绪事件（只返回就绪的）
```
```
// Nginx 默认使用 epoll（Linux）
// 在 Linux 上，Nginx 自动选择 epoll
// 一个 Worker 一个 epoll 实例 → 管理成千上万连接
```
水平触发 vs 边缘触发
```
// 水平触发（LT，默认）：只要缓冲区有数据就通知
// 边缘触发（ET）：数据到来时通知一次（需一次读完）

// Nginx 用 ET 模式（高效，减少通知次数）
```
### 异步非阻塞
```
// 非阻塞：read() 立即返回（有数据读数据，没数据返回 EAGAIN）
// 异步/事件驱动：不用轮询，靠 epoll 通知

// Nginx 的处理模型：
// ① 用 epoll 监听所有连接
// ② 事件就绪 → 处理 → 处理完继续等
// ③ 整个过程不阻塞（除非真的没活干）

// 效果：
// 一个 Worker 处理数万连接，不阻塞
```
事件循环
```
while (true) {
    events = epoll_wait(epfd, ...);   // 等事件（阻塞在这，但有事件才醒）
    for (event : events) {
        // 处理就绪的事件（读/写/连接）
        handle_event(event);
    }
}
```
```
// 这就是"事件循环"——Nginx 的核心
// 和 Netty 的 EventLoop、Node.js 的 EventLoop 一个思路
```
### 多进程+多核（无锁）
```
// ① 多个 Worker 进程 → 分散到多个 CPU 核
// ② 进程内存隔离 → 无需锁（避免锁竞争开销）
// ③ CPU 亲和绑定 → 减少进程迁移

worker_processes auto;                    // = CPU 核数
worker_cpu_affinity auto;                 // 自动绑核
```
```
// 对比 Apache（多线程/多进程 + 锁）：
// Nginx 天然无锁，高并发下性能更稳
```
### 内存池
```
// 问题：频繁 malloc/free 有开销（分配器锁、内存碎片）

// Nginx 方案：内存池
// ① 预先申请大块内存
// ② 小块内存从池里分配（指针移动，极快）
// ③ 连接结束 → 整个池一次性释放（不逐个 free）

// 两层：
// ① 连接内存池（每个连接一个，生命周期=连接）
// ② 请求内存池（每个请求一个，请求结束整体释放）

// 好处：
// ① 减少 malloc/free 次数
// ② 避免内存碎片
// ③ 释放简单（整块回收）
```
```
// 与 Netty 内存池对比：
// Nginx：连接/请求级内存池
// Netty：PooledByteBufAllocator（更复杂的规格化池）
// 思路一致：减少分配开销
```
### 零拷贝（sendfile）
```
// 场景：Nginx 返回静态文件
// 传统：磁盘 →[DMA]→ 内核缓冲 →[CPU]→ 用户缓冲 →[CPU]→ socket 缓冲 →[DMA]→ 网卡
//       有 2 次 CPU 拷贝

// sendfile：磁盘 →[DMA]→ 内核缓冲 →[DMA]→ 网卡
//       0 次 CPU 拷贝！

// Nginx 配置：
location /static/ {
    sendfile on;              # 开启零拷贝  静态文件发送用零拷贝
    tcp_nopush on;            # 配合 sendfile，攒够一个包再发
    tcp_nodelay on;           # 小数据立即发（禁 Nagle）
}
```
